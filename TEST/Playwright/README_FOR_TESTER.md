## 🐛 2. Automated Bug Reporting Integration

All tests in this suite are equipped with a self-healing reporting wrapper:
*   If **any element is missing, a console error occurs, or route guards fail**, the `afterEach` hook intercepts the failure.
*   The test automatically triggers the **Bug Reporter Widget** floating on the screen.
*   The widget logs in using:
    *   **Access ID**: `DEV-NIVED`
    *   **Password**: `Nived@123`
*   The script writes a detailed bug report containing:
    *   The test name
    *   The failure status
    *   Precise steps/error description
*   The bug is sent directly to the database before the test exits, ensuring complete trace capture in your development bug-tracking list!

## 🏃‍♂️ 3. Execution Instructions

You can run the tests using our pre-built runner scripts from your terminal at the project root.

### Standard PowerShell Command (Windows)
```powershell
.\TEST\Playwright\run_tests.ps1
```

### Native Batch Command (Windows Double-Click)
Double-click `TEST/Playwright/run_tests.bat` or run:
```powershell
.\TEST\Playwright\run_tests.bat
```

### Manual Testing Commands
If you prefer running individual commands, run these from the project root:

1. **Run all tests (headless)**:
   ```bash
   npx playwright test
   ```

2. **Run tests with interactive UI mode (Highly Recommended)**:
   ```bash
   npx playwright test --ui
   ```

3. **Debug a specific role's test**:
   ```bash
   npx playwright test TEST/Playwright/tests/student.spec.ts --debug
   ```

## 📂 4. Test Files & Outputs

All materials generated by Playwright are stored in your `TEST/Playwright/` folder for clean organization:

*   **Test Specifications**: `TEST/Playwright/tests/`
    *   `student.spec.ts` (Happy path + profile audits + security limits)
    *   `faculty.spec.ts` (Dashboard stats + verification scanner checks)
    *   `cc.spec.ts` (Dashboard metrics + events planners)
    *   `hod.spec.ts` (Approval tabs + activity listings)
    *   `pr.spec.ts` (Scanner access + bundle audits)
    *   `eventApproval.spec.ts` (CC proposal -> Teacher verification -> HOD publication workflow)
    *   `registrationScanning.spec.ts` (Student Event Registration -> PR Attendance scan)
    *   `feedbackReporting.spec.ts` (Student Feedback submission -> CC Post-Event Report -> PR Audit approval)
    *   `masterWorkflow.spec.ts` (Ultimate master sequential E2E test executing the complete product lifecycle)
    *   `bugReporter.spec.ts` (Standalone widget functional integration test)
*   **Helper Utilities**: `TEST/Playwright/utils/bugReporter.ts` (Automatic widget submission)
*   **Results & Reports**: `TEST/Playwright/`
    *   **HTML interactive dashboard**: `TEST/Playwright/playwright-report/`
    *   **JSON reports**: `TEST/Playwright/test-results/report.json`
    *   **JUnit XML summaries**: `TEST/Playwright/test-results/junit.xml`
    *   **Screenshots & Videos**: Automatically saved here upon any test failure or completion.
